A Camada de Transporte

A Camada de Rede (IP) encontra o caminho da origem até a máquina de destino.

Mas, dentro da máquina, qual aplicativo deve receber a mensagem? O Navegador? O Jogo? O Spotify?

A resposta: Portas Lógicas.

ANALOGIA DO CONDOMÍNIO (Fale isso para a turma):
- Endereço MAC (Enlace): É o chassi do carro do carteiro.
- IP (Rede): É o CEP e o número do prédio. Faz o pacote chegar na portaria correta.
- Porta Lógica (Transporte): É o número do apartamento. Não adianta entregar no prédio se não souber se o pacote é pro navegador (80) ou pro jogo (aleatória).

TCP: Transmission Control Protocol

  • Confiável: Garante que o pacote chegou. Se perder, retransmite.
  • Orientado à Conexão: Faz um "acordo" antes de enviar dados.
  • Ordenado: Monta as peças na ordem correta.
  • Analogia: Correio com Aviso de Recebimento (AR).
  • Uso: E-mail, Navegação Web, Transferência de Arquivos.

O "Aperto de Mão" (3-Way Handshake)

Antes de enviar qualquer dado real, o TCP negocia a conexão em 3 etapas:

SYN ➔ "Posso falar com você?"

SYN-ACK ➔ "Pode sim, estou ouvindo. E você me ouve?"

ACK ➔ "Ouço perfeitamente. Vamos começar!"

DICA FGV: As bancas amam cobrar a ordem exata das flags: SYN -> SYN-ACK -> ACK. Pense num telefonema: "Alô?" -> "Tô ouvindo, quem é?" -> "Sou eu, vou começar a falar".

PORTAS EFÊMERAS: Lembre os alunos que a porta de destino é a 80 ou 443, mas a porta de origem do cliente (PC do aluno) NUNCA é a 443! O SO escolhe uma porta alta e aleatória (ex: 51324) para saber para qual aba do navegador ele deve devolver a resposta quando o servidor responder.

UDP: User Datagram Protocol

  • Rápido: Não confere se chegou.
  • Sem Conexão: Apenas dispara os dados.
  • Sem retransmissão: Se perder, perdeu. A vida segue.
  • Analogia: Transmissão de rádio FM.
  • Uso: Streaming de Vídeo, Jogos Online, VoIP (Ligação).
O MITO DO UDP SER RUIM:
Alunos acham que UDP é ruim porque perde pacote. Diga a eles: "Imagine jogar CS:GO via TCP. Se perder um pacote indicando a posição do inimigo, o jogo trava esperando retransmitir o dado antigo. No UDP, você dá uma travadinha de 1ms, perde o passado, e já recebe a nova posição atualizada no próximo quadro. Para vídeo e jogos em tempo real, o atraso é infinitamente pior que a perda de 1 pixel!"

🔎 Revisão da Pesquisa: Protocolos de Aplicação

🌐 HTTP (80) vs HTTPS (443)

Função: Transferência de páginas Web (HTML).

Diferença: O HTTP envia dados em texto claro (qualquer um na rede lê sua senha). O HTTPS aplica criptografia TLS/SSL (cadeado). Ambos usam TCP.

📖 DNS (Porta 53 — UDP/TCP)

Função: A "Agenda Telefônica" da Internet.

Traduz nomes humanos (www.google.com) para endereços IP (142.250.79.4). Usa UDP para consultas rápidas do dia a dia.

🎟️ DHCP (Portas 67/68 — UDP)

Função: Entrega automática de configuração IP.

Quando você conecta no Wi-Fi, o DHCP entrega IP, Máscara, Gateway e DNS via processo DORA (Discover, Offer, Request, Ack).

🔐 SSH (22) & 📁 FTP (20/21)

SSH (Porta 22 - TCP): Terminal remoto seguro e criptografado para administrar servidores Linux.

FTP (Portas 20/21 - TCP): Transferência de arquivos (21 p/ Controle, 20 p/ Dados).

CONFERÊNCIA DA PESQUISA:
Peça para 3 ou 4 alunos lerem o que anotaram no caderno sobre HTTP/HTTPS, DNS e DHCP antes de revelar cada card com a seta! Destaque o acrônimo DORA do DHCP (muito cobrado em provas).

🔎 Protocolos de Rede e Diagnóstico (Camada 3)

📍 IP (Internet Protocol) — O "CEP" da Máquina

Responsável pelo endereçamento lógico (IPv4 / IPv6) e pelo roteamento de pacotes entre redes diferentes. Opera sem garantia de entrega (quem garante a entrega é o TCP na camada de cima!).

📡 ICMP (Ping e Tracert)

Protocolo de mensagens de controle e diagnóstico. Não transporta dados de usuário nem usa portas! É o motor por trás do comando ping (Echo Request / Echo Reply).

🔗 ARP (IP ➔ Endereço MAC)

Traduz um endereço lógico conhecido (IP) no endereço físico da placa de rede (MAC Address) dentro da rede local. Comando: arp -a.

PONTO DE CONEXÃO:
Mostre como todos trabalham juntos: 1) DHCP dá o IP ao PC; 2) DNS descobre o IP do site; 3) ARP descobre o MAC do roteador; 4) TCP faz o 3-Way Handshake na porta 443; 5) HTTPS baixa a página segura!
