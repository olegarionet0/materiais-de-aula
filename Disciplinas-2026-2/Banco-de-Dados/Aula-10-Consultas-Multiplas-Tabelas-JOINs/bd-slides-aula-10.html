Por que dividir em tabelas?

❌ Tabela Única (Desastre):
Repetir 'Eletrônicos' 1.000 vezes. Se a categoria mudar para 'Tecnologia', teremos que alterar 1.000 linhas!
✔️ Solução Relacional (Normalização):
Criamos a tabela categorias e em produtos guardamos só a Chave Estrangeira (categoria_id).
CONCEITO:
Isso é Integridade Referencial. Evita inconsistência (ex: alguém digitar 'Eletro' e outro digitar 'Eletronicos').

O Primeiro INNER JOIN

Busca apenas onde há interseção mútua entre as duas tabelas:

SELECT p.nome AS produto, p.preco, c.nome AS categoria
FROM produtos AS p
INNER JOIN categorias AS c ON p.categoria_id = c.id;
📌 ON p.categoria_id = c.id é a ponte: compara a Chave Estrangeira (FK) com a Primária (PK).
DESTAQUE PEDAGÓGICO:
Sem a cláusula ON, o banco faz um Produto Cartesiano (multiplica todas as linhas por todas as linhas). O ON é o filtro de ligação!

-- Desafio 1: INNER JOIN com Ordenação
SELECT p.nome AS produto, p.preco, c.nome AS categoria
FROM produtos AS p
INNER JOIN categorias AS c ON p.categoria_id = c.id
ORDER BY c.nome ASC;

-- Desafio 2: INNER JOIN com Filtro WHERE
SELECT p.nome AS produto, p.preco, c.nome AS categoria, c.setor
FROM produtos AS p
INNER JOIN categorias AS c ON p.categoria_id = c.id
WHERE c.setor = 'Tecnologia' AND p.preco > 150.00;
📌 Ordem Sagrada das Cláusulas: SELECT ➔ FROM ➔ INNER JOIN ... ON ➔ WHERE ➔ ORDER BY.
COMENTÁRIO:
Mostre que a ordem das cláusulas na SQL é sagrada: SELECT -> FROM -> INNER JOIN ... ON -> WHERE -> ORDER BY.

E se um produto não tiver categoria?

INNER JOIN

Rigoroso: só traz correspondência nas duas tabelas.

Resultado: O 'Cabo Adaptador USB' (sem categoria) some do relatório!

LEFT JOIN

Inclusivo: preserva todos da esquerda (produtos), mesmo sem par na direita.

Resultado: O 'Cabo Adaptador USB' aparece com categoria NULL.

ANALOGIA DA LISTA DE CHAMADA:
INNER JOIN = Só entram os alunos que trouxeram autorização.
LEFT JOIN = Lista todos os alunos da turma; quem não trouxe autorização fica com o campo em branco (NULL).

LEFT JOIN na Prática (Auditoria de Dados)

-- Traz TODOS os produtos, com ou sem categoria:
SELECT p.nome AS produto, p.preco, c.nome AS categoria
FROM produtos AS p
LEFT JOIN categorias AS c ON p.categoria_id = c.id;

-- Desafio 4: Caçando Produtos Órfãos (sem categoria):
SELECT p.nome, p.preco
FROM produtos AS p
LEFT JOIN categorias AS c ON p.categoria_id = c.id
WHERE c.id IS NULL;
💡 Uso no Mundo Real: Essa query é usada por DBAs e analistas para encontrar cadastros incompletos no sistema!
DICA FGV/CONCURSOS:
A pegadinha de prova clássica é comparar nulo com igual (WHERE c.id = NULL). O correto em SQL é sempre IS NULL ou IS NOT NULL!

Relatório Gerencial: JOIN + Agregações

SELECT 
    c.nome AS categoria,
    COUNT(p.id) AS total_produtos,
    AVG(p.preco) AS preco_medio
FROM categorias AS c
INNER JOIN produtos AS p ON c.id = p.categoria_id
GROUP BY c.nome
ORDER BY total_produtos DESC;
📊 Resultado: Junta o poder do JOIN com o que aprendemos na aula passada (COUNT, AVG e GROUP BY)!
FECHAMENTO:
Essa é a query que o gerente de uma loja pede toda semana. Uma única consulta traz o nome da categoria, a quantidade de itens no estoque e o preço médio.
