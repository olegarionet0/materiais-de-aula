🔗 O que é uma Chave Estrangeira?


Uma Foreign Key (FK) é uma coluna em uma tabela que guarda o valor da Chave Primária de outra tabela.

Ela é a implementação do losango (relacionamento) do DER no banco relacional.
Metáfora: A ficha de empréstimo da biblioteca contém o RA do aluno e o código do livro. No banco, essa ficha é a tabela com duas FKs.

🛡️ Integridade Referencial


O SGBD garante que uma FK nunca pode apontar para um registro inexistente.


❌ Rejeitado

INSERT empréstimo com
id_aluno = 999
mas aluno 999 não existe

✅ Aceito

INSERT empréstimo com
id_aluno = 3
e aluno 3 existe na tabela

📐 Regras por Cardinalidade


CardinalidadeRegraOnde vai a FK
1:N (um para muitos) FK no lado N Na tabela do "muitos"
1:1 (um para um) FK em qualquer lado + UNIQUE Em um dos dois lados
N:N (muitos para muitos) Criar tabela associativa Nova tabela intermediária

📌 Cenário 1 — Relacionamento 1:N

"Um professor leciona muitas turmas. Uma turma tem um único professor."


Regra: FK vai para a tabela do lado N → turma recebe id_professor


Tabela: turma
ColunaTipoRestrição
id_turmaINTPK, AUTO_INCREMENT
nomeVARCHAR(20)NOT NULL
turnoVARCHAR(10)—
id_professorINTFK → professor(id_professor)

📌 Cenário 2 — Relacionamento 1:1

"Cada funcionário tem um crachá único. Cada crachá pertence a um funcionário."


Regra: FK + UNIQUE (garante que nenhum funcionário se repete)


Tabela: cracha
ColunaTipoRestrição
id_crachaINTPK, AUTO_INCREMENT
numero_serieVARCHAR(20)UNIQUE, NOT NULL
id_funcionarioINTFK + UNIQUE
O UNIQUE na FK é o que transforma o 1:N em 1:1 — impede que um funcionário apareça em mais de um crachá.

📌 Cenário 3 — Relacionamento N:N

"Um aluno pode pegar vários livros. Um livro pode ser emprestado por vários alunos."

Regra: Criar tabela associativa emprestimo com duas FKs


Tabela: emprestimo
ColunaTipoRestrição
id_emprestimoINTPK, AUTO_INCREMENT
id_alunoINTFK → aluno(id_aluno)
id_livroINTFK → livro(id_livro)
data_retiradaDATENOT NULL
data_devolucaoDATE— (NULL = não devolveu)

⚠️ Regra de Ouro do N:N


Um relacionamento N:N

sempre gera uma nova tabela.


Nunca tente colocar a FK diretamente
em uma das tabelas existentes.


Os atributos do relacionamento (ex: datas)
também ficam nessa tabela associativa.

🏆 Desafio em Dupla

Minimundo: Uma escola tem professores e disciplinas. Um professor pode lecionar várias disciplinas. Uma disciplina pode ser lecionada por vários professores (em turmas diferentes).

Cada professor tem: nome, CPF e email.
Cada disciplina tem: nome e carga horária.

Tarefas:

  1. Identificar as entidades e a cardinalidade
  2. Montar as tabelas com PKs, FKs e tipos de dados
  3. Criar a tabela associativa (se necessário)

✅ O que aprendemos hoje

  • FK é a coluna que implementa o relacionamento (losango do DER)
  • Integridade referencial: FK só aceita valores que existem na tabela pai
  • 1:N → FK no lado N
  • 1:1 → FK + UNIQUE
  • N:N → tabela associativa com 2 FKs
