🛡️ Dica de Engenharia: O Arquivo Local

⚠️ O Problema: A interface web do phpMyAdmin é stateless. Se você apertar F5 por engano, fechar a aba ou a conexão reiniciar, toda a query digitada é perdida.
💡 A Solução Profissional:

  3. Escreva, comente e salve a query no editor.
  4. Copie e cole na caixa SQL do phpMyAdmin apenas para executar.

🔍 Bloco 1: Filtros com WHERE

A cláusula WHERE restringe as linhas retornadas:

-- Operadores de Comparação: =, !=, <, >, <=, >=
SELECT * FROM produtos WHERE preco > 100.00;

-- Operador Lógico AND (ambas as condições verdadeiras)
SELECT nome, preco FROM produtos 
WHERE categoria = 'Eletrônicos' AND ativo = 1;

-- Operador Lógico OR (pelo menos uma verdadeira)
SELECT * FROM produtos 
WHERE categoria = 'Papelaria' OR preco < 50.00;

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Explique a precedência lógica: o MySQL avalia expressões booleanas linha por linha. Aspas simples são obrigatórias para strings (`'Papelaria'`), enquanto números (`100.00`) não usam aspas.

🛡️ DML Seguro: A Regra do SELECT Prévio

🚨 Nunca execute UPDATE ou DELETE diretamente em produção!
Se o filtro WHERE estiver errado ou ausente, a alteração afeta a tabela inteira.

Regra de Ouro do DBA:

1º Teste com SELECT:

SELECT * FROM produtos WHERE categoria = 'Eletrônicos';

2º Conferiu as linhas? Execute o UPDATE:

UPDATE produtos SET preco = preco * 1.10 WHERE categoria = 'Eletrônicos';

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Destaque que em bancos reais sem transações ativas (`autocommit=1`), um `DELETE` ou `UPDATE` executado não tem Ctrl+Z imediato. A disciplina do `SELECT` prévio previne desastres operacionais.

👉 Obrigatório: execute o SELECT correspondente antes do DELETE.

📶 Bloco 2: Ordenação (ORDER BY)

Classifica a ordem de exibição dos registros retornados:

-- Ordem Crescente (padrão): ASC (Ascending - A-Z, 0-9)
SELECT * FROM produtos ORDER BY preco ASC;

-- Ordem Decrescente: DESC (Descending - Z-A, 9-0)
SELECT * FROM produtos ORDER BY preco DESC;

-- Ordenação Múltipla:
SELECT * FROM produtos ORDER BY categoria ASC, preco DESC;

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Explique que sem `ORDER BY`, a ordem dos registros retornados pelo banco não é garantida pelo padrão SQL (depende do plano de execução do banco ou da ordem do índice físico). O `ORDER BY` garante determinismo visual.

📄 Controle de Volume (LIMIT)

A cláusula LIMIT restringe a quantidade máxima de linhas devolvidas:

-- Retorna apenas os 3 primeiros registros encontrados
SELECT * FROM produtos LIMIT 3;

-- Muito usado em rankings combinando com ORDER BY:
SELECT nome, preco FROM produtos 
ORDER BY preco DESC 
LIMIT 5; -- Top 5 produtos mais caros
🎯 Aplicações reais: Paginação em sites (ex: 20 produtos por página), exibição de "Top 10" e proteção contra sobrecarga em bancos com milhões de registros.

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Em sistemas web reais com 1 milhão de clientes, um `SELECT * FROM clientes` sem LIMIT derrubaria a memória do servidor PHP/NodeJS. O LIMIT é obrigatório em sistemas escaláveis.

⏱️ Tempo: 7 minutos

Conteúdo de Apoio para Explicação:

Conteúdo de Apoio para Explicação:

🧮 Bloco 3: Funções de Agregação

Transformam múltiplas linhas em um único valor calculado:

  • COUNT(*): Contagem de linhas.
  • SUM(coluna): Soma numérica dos valores.
  • AVG(coluna): Média aritmética simples.
  • MIN(coluna): Menor valor da coluna.
  • MAX(coluna): Maior valor da coluna.
-- Exemplo com apelido de coluna (AS):
SELECT COUNT(*) AS total_itens, AVG(preco) AS media_valor 
FROM produtos;

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Explique o propósito do `AS`: sem ele, o cabeçalho da coluna na tabela de resultado ficaria com o nome literal `COUNT(*)` ou `AVG(preco)`, o que é inadequado para integração em APIs e interfaces.

⏱️ Tempo: 7 minutos

⚡ Desafio 7 (Métricas Consolidadas)

Elabore uma única query SQL que retorne as seguintes colunas com os respectivos apelidos (AS):

  • Total de produtos cadastrados ➔ total_produtos
  • Média de preços ➔ media_precos
  • Menor preço ➔ menor_preco
  • Maior preço ➔ maior_preco
  • Soma de todos os preços ➔ soma_precos

Conteúdo de Apoio para Explicação:

Dinâmica de Sala: Incentive os alunos a separarem as funções agregadoras por vírgula na cláusula SELECT.

✅ Gabarito: Desafio 7

-- Desafio 7: Sumário Estatístico da Loja
SELECT 
    COUNT(*) AS total_produtos,
    AVG(preco) AS media_precos,
    MIN(preco) AS menor_preco,
    MAX(preco) AS maior_preco,
    SUM(preco) AS soma_precos
FROM produtos;
💡 Resultado: Retorna uma única linha com o consolidado de toda a tabela.

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Mostre que os números retornados refletem o estado atual da tabela após o reajuste do Desafio 3 e a exclusão do Desafio 4.

📂 Agrupamento de Dados: GROUP BY

E se quisermos saber as métricas por categoria?

SELECT categoria, COUNT(*) AS quantidade, AVG(preco) AS preco_medio
FROM produtos
GROUP BY categoria;
📌 Regra Fundamental do GROUP BY:
Toda coluna presente no SELECT que não for uma função agregadora (como COUNT, AVG) deve constar no GROUP BY!

Conteúdo de Apoio para Explicação:

Teoria/Explicação: Essa é a regra mais cobrada em mercado e entrevistas técnicas. Se você colocar `SELECT nome, categoria, COUNT(*) FROM produtos GROUP BY categoria`, o banco não sabe qual 'nome' exibir para a categoria inteira, gerando inconsistência ou erro SQL de `only_full_group_by`.

⏱️ Tempo: 8 minutos

⚡ Desafio 8 (Relatório por Categoria)

Gere um relatório executivo agrupado por categoria contendo:

  3. O preço médio: AVG(preco) AS preco_medio.

👉 Ordene o resultado final pela quantidade de itens de forma decrescente (ORDER BY total_itens DESC).

Conteúdo de Apoio para Explicação:

Dinâmica de Sala: Esta é a query de encerramento do laboratório que consolida `SELECT`, agregação, `GROUP BY` e `ORDER BY`.
