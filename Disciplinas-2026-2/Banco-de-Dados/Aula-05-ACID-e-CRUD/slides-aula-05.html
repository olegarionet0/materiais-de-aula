⚠️ O Problema: Transferência Bancária

Um sistema executa uma transferência de R$ 500 do João para a Maria:


1️⃣ Debitar R$ 500 da conta do João → ✅ feito

2️⃣ Creditar R$ 500 na conta da Maria → 💥 servidor caiu!


Resultado: João perdeu R$ 500. Maria não recebeu nada.
O banco de dados ficou em estado inconsistente.

Como evitar isso? Com Transações.

🔁 O que é uma Transação?


Um conjunto de operações que devem ser executadas como uma unidade indivisível.

✅

COMMIT

Tudo funcionou
→ confirma as mudanças

↩️

ROLLBACK

Algo falhou
→ desfaz tudo

Parte 2

As Propriedades ACID

Os quatro pilares que todo SGBD sério precisa garantir.

🅐 Atomicidade

A Tudo ou Nada.

A transação é atômica: não existe "meio-feita".

  • Todos os passos executam → COMMIT
  • Qualquer passo falha → ROLLBACK de tudo
Exemplo: Na transferência bancária, se o crédito falhar, o débito é automaticamente desfeito. O João não perde dinheiro.

🅒 Consistência

C Sempre válido.

O banco deve passar de um estado válido para outro estado válido.

PK, FK, NOT NULL e regras de negócio são sempre respeitadas.

Exemplo: Se a regra diz que nota ∈ [0, 10], um UPDATE que tente gravar nota = -5 é rejeitado. A Consistência garante que a regra nunca seja violada.

🅘 Isolamento

I Sem interferência.

Transações simultâneas não se enxergam enquanto estão em andamento.

Uma transação não vê as mudanças de outra que ainda não fez COMMIT.

Exemplo: Dois caixas de supermercado registrando vendas ao mesmo tempo. O banco gerencia o acesso para que um não sobrescreva os dados do outro.

🅓 Durabilidade

D Permanente após COMMIT.

Uma transação confirmada persiste para sempre — mesmo que o servidor caia logo depois.

O SGBD usa logs de transação em disco para garantir recuperação.

Exemplo: Você paga no Pix e recebe a confirmação. Se o servidor reiniciar 2 segundos depois, o pagamento continua registrado.

🧠 Mnemônico ACID


Atômica  —  tudo ou nada
Consistente  —  sempre válido
Isolada  —  sem interferência
Durável  —  permanente após commit

Parte 3

CRUD

As 4 operações que qualquer sistema realiza em um banco de dados.

🔄 As 4 Operações CRUD


LetraOperaçãoSQLO que faz
C Create (Criar) INSERT INTO Insere novo registro
R Read (Ler) SELECT Consulta registros
U Update (Atualizar) UPDATE Modifica registros
D Delete (Deletar) DELETE FROM Remove registros

🖥️ CRUD em Qualquer Sistema


Toda tela de sistema que você vai desenvolver usa CRUD:


C — Formulário de cadastro de aluno

R — Lista de chamada da turma

U — Edição do endereço no perfil

D — Botão "Excluir aluno transferido"

CRUD + ACID:

Toda operação CRUD dentro de uma transação segue as regras ACID. Se um INSERT falhar no meio, o SGBD faz ROLLBACK — o registro não fica pela metade.

👀 Spoiler: O que vem a seguir

Nas próximas aulas vamos escrever SQL de verdade:


-- CREATE TABLE (DDL)
CREATE TABLE aluno (
  id_aluno INT AUTO_INCREMENT PRIMARY KEY,
  nome     VARCHAR(100) NOT NULL
);

-- INSERT (CRUD - C)
INSERT INTO aluno (nome) VALUES ('Maria Silva');

-- SELECT (CRUD - R)
SELECT * FROM aluno;

✅ O que aprendemos hoje

  • Transação = bloco indivisível (COMMIT ou ROLLBACK)
  • Atômica · Consistente · Isolada · Durável
  • CRUD = Create / Read / Update / Delete
  • CRUD ↔ INSERT / SELECT / UPDATE / DELETE
